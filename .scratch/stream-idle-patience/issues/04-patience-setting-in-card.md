# 04: 排队耐心档位——可保存的枚举与卡片下拉

**P2 · 规模 M · 依赖 无**

**Status:** ready-for-agent
**Category:** enhancement

## What to build

卡片上出现一个"排队耐心"下拉框，三档：2 分钟 / 4 分钟 / 6 分钟，默认 4 分钟。

选择能被保存、重开卡片后仍然显示所选的那一档。**这一张只负责"能选、能存、能回显"，还不要让
它改变任何超时行为**——那是下一张的事。分开的理由是这张要横跨设置声明、读取、保存白名单、卡片
状态与两套文案；把它和"让值生效"放一起会大到无法在一个上下文里做完。

用枚举而不是数字输入：枚举让"越界"从根上消失。用户手改配置写成不存在的档位时，schema 解析失败，
读取那一侧回落到默认档并留下用户可见的告警——不允许静默用默认值（红线：不新增静默失败分支）。

## Blocked by

None (can start immediately).

## Acceptance criteria

- [ ] 设置里存在一个新的枚举字段，三档取值与默认值如上
- [ ] 该字段在保存白名单里，且与设置声明的字段名一致
- [ ] 卡片上的下拉位于"保存"按钮之上（本仓既有约定：凡保存会带走的设置都排在提交条之上）
- [ ] 选择后保存，写入成功并读回校验通过；重开卡片时回显所选档位
- [ ] 保存失败时有可见的错误状态，不显示"已保存"
- [ ] 读到不存在或非法的档位时回落到默认档，并且该回落是可见的（日志或卡片提示）
- [ ] 中英两套文案都有，且卡片文案门禁通过
- [ ] 该字段被加进"每个字段都必须 volatile"那条测试的硬编码清单里，否则该承诺对新字段是空的
