# 01: 空闲窗口语义与按阶段分类

**P1 · 规模 M · 依赖 无**

**Status:** ready-for-agent
**Category:** bug

## What to build

一次单次请求只要还在持续产出内容，跑多久都不会被打断；真正卡死的连接在**空闲窗口**到期时被判死。

判定之后的处置按阶段分开：

- **第一帧之前**卡死：这时什么都没发出去，重试不会产生重复内容，因此翻译成可重试的排队拒绝。
- **第一帧之后**卡死：这时前半段答案已经交给调用方，重试会重复它，因此翻译成不可重试的普通错误。

同时要保证被打断时连接立刻释放，且清理阶段本身不会把这次单次请求卡住——否则错误永远到不了
重试循环，用户只会看到一次无声的悬挂。

## Blocked by

None (can start immediately).

## Acceptance criteria

- [ ] 一个持续产出、总时长远超空闲窗口的流能完整结束，不被截断
- [ ] 一个沉默时间短于空闲窗口、但长于旧的绝对期限的流能正常结束
- [ ] 响应头之后一直沉默：得到可重试的排队拒绝，尝试次数大于一，且总耗时受排队耐心约束
- [ ] 产出一个 chunk 之后沉默：得到不可重试的错误，不重试，且不产生重复内容
- [ ] 完全等不到响应头：仍是可重试的排队拒绝（既有行为不得回退）
- [ ] 判定为卡死时，连接在有限时间内被释放，不依赖运行时的传输层超时兜底
- [ ] 单次请求的入口可以接受一个可选的限制参数（空闲窗口、排队耐心），便于测试用小值驱动
- [ ] 上述七条行为先写成红的测试，再改实现
