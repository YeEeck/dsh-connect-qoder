# 05: 让档位真正生效——每请求读取与天花板推导

**P2 · 规模 M · 依赖 01, 04**

**Status:** ready-for-agent
**Category:** enhancement

## What to build

选了档位之后，三个数值随之改变并真的影响行为：

- **排队耐心** = 档位值（2 / 4 / 6 分钟）
- **空闲窗口** = 排队耐心的一半（60 / 120 / 180 秒）
- **流空闲天花板** = 排队耐心加 60 秒（180 / 300 / 420 秒）

每次单次请求读一次当前档位，与宿主读流空闲天花板的节奏一致。档位变化要让 provider profile 里的
天花板跟着更新，走设置保存后已有的刷新链路，不需要重启。

**"空闲窗口 < 排队耐心 < 流空闲天花板"必须由构造保证**，不是靠三个常量碰巧满足大小关系。
这条不等式是承重的：任何一层先于内层触发，都会把一个可分类、可重试的失败降级成宿主的盲目重试，
每次重试都是一整套全新耐心，并额外消耗每日请求额度。

推导写成纯函数并直接测试，不要把它埋进装配层——那里没有测试可以到达。

## Blocked by

01（空闲窗口必须可按单次请求注入）、04（档位必须先能保存）。

## Acceptance criteria

- [ ] 三个数值由档位推导，且不等式对三档都成立（含默认档）
- [ ] 推导是纯函数，可被裸 `node --test` 直接 import 并断言
- [ ] 选择一个档位后，下一次单次请求实际使用新的空闲窗口与耐心（改变选择不影响进行中的请求）
- [ ] 流空闲天花板随档位更新，且不需要重启 DSH
- [ ] 未设置该字段时使用默认档，行为与"显式选择默认档"完全一致
- [ ] 一个测试钉住不等式本身，防止将来有人单独调大某一项而破坏它
